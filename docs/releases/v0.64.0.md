# podcrates v0.64.0

The sixty-fourth release of podcrates. It carries the far end's line of a
wait that holds in `pod-session` (podssh's stalled resume), the roots of
the host in a network lab with a way out, the filter of `sni-allowlist` on
each address and the IPv6 default route of `ipv6-only` in `pod-lab`, the
opaque directories of an overlay root in a user namespace in `pod-enter`,
a stand-in of `pod-lab` that ignores SIGPIPE (podvm), the normative wire
of the link of `pod-link` with its cases, its measurement and a data path
with no allocation for each frame, and a fix of the drift check of the
sources.

## Crates

| Crate | Change | Consumers |
| --- | --- | --- |
| `pod-session` | The far end sends the event `session.stall` (`pump::STALL`, Info, on the sink of `Keeper::with_tell`) once for each wait of the reader of the target that holds 20 s (`pump::STALL_AFTER`): for room in the replay buffer or the window, for the writer of the link, for room of the records sent again, or on a target that sent no byte while it took bytes of the client. The line gives the offsets sent and acknowledged, the bytes kept, the room and the window. The line `session.resume` ends with the room of the replay buffer and the window (T-767, partial, PodUtils/podssh#283 ask 3) | podssh, podnet |
| `pod-enter` | The overlay root of the namespace rung in a user namespace (the one that the rung makes, or the one of a caller that is uid 0 of a user namespace that is not the initial one) has `userxattr` (`USERXATTR`): overlayfs reads and writes `user.overlay.*` there; a kernel before 5.11 gets the mount with no such option. The check before the fork reads the one opaque attribute that the mount reads: `user.overlay.opaque` in a user namespace, `trusted.overlay.opaque` for a host root (T-755; call C765) | podvm, podrunner |
| `pod-lab` | With a way out, the certificate file of the lab holds the roots that the host trusts after the CAs of the lab (`SSL_CERT_FILE` of the host, else its first system bundle): a program in the lab checks a real server past the way out (T-792, PodUtils/podssh#285). `sni-allowlist` filters a ClientHello to port 443 of each IPv4 address, by a local route of `0.0.0.0/0` on the loopback; a connect to another port gets `ECONNREFUSED`. `ipv6-only` has a dummy device `lab0` with `fd00:6c61:62::2/64` and the IPv6 default route through it; the part `ipv6-reaches` reads the row `read(/proc/net/ipv6_route)` (T-747; call C764). ## Tests and checks

The live test of the upper layer of `pod-enter` checks the option
`userxattr` of the overlay in a user namespace in `/proc/self/mountinfo`:
the kernel of Ubuntu hides an opaque directory with no such option, so the
plant `enter-overlay-no-userxattr` was missed on the runner (T-755). The
seeds of the fuzz target `link_frame` are the cases of
`tests/wire/frames.txt` (T-775).

The job `sources` of `upstream.yml` reads a file that a crate took in part
at the commit of its own take; podnet's `pod-manual` take is at `9217b0b`;
podssh's block of `pod-manual` is at `5340fbb` (T-793 to T-795; call C763).
The job is green on each consumer.

## How a consumer takes it

Each podcrates dependency names the tag `v0.64.0`; `issue-sync.yml@v0.64.0` takes `podcrates_ref: v0.64.0`.

- podssh: keep the node's lines in the m6 test: at the next stall, the line `session.stall` names the wait of the node's reader of the target.
- Each project that runs a network lab with `--way-out`: a program in the lab needs no certificate file of its own for a server past the way out.
- podvm, podrunner: an upper directory of a run with no capabilities keeps its whiteouts and opaque directories as `user.overlay.*`; a directory that an earlier run marked opaque with `trusted.` is not opaque in a user namespace.
- podvm: you can remove your handler of SIGPIPE before `pod_lab::dispatch`; `fedorapeople.org` is in `pod-services` (`fedora-virtio-win`): remove it from `WAITING`.
- podnet, podssh: `pod-link` has no change of the wire; `WIRE.md` is its contract, for a second reader of the wire.
- podnet: `ipv6-only` shows an IPv6 default route on a device that is not the loopback (`pod_dns::route::has_default_route`).

## Breaking

- `pod_session::pump::Watch` has the field `stall`; it moved to `pump/watch.rs` (the path `pod_session::pump::Watch` stays).
- `pod_lab::net::Net` has the field `each_v4`; `pod_lab::net::NetFact` has the variant `HelloElsewhere`: a struct literal or a `match` names them.
- The line `session.resume` has more words at its end.

## Known defect

- `pod-session`: the cause of the stalled resume of PodUtils/podssh#283 is open (T-767, partial); a spare waits 20 s when a full link holds the writer (T-768, open).
- `pod-enter`: the ids of the plan do nothing for a caller that is root of the initial namespace (T-791, open, when a consumer asks).
- The nightly: armv7 (T-789), riscv64 (T-766).
- `pod-lab`: the certificate file of a way out on a host with no bundle holds no root (T-797).
- `pod-link`: the tcp carrier allocates about 3 times for each `DATA` frame, in its TLS (T-798).
- `pod-lab`: `upgrade-refused` has no row; `ipv6-only` refuses on a kernel with no IPv6.
- `pod-gsr` on Windows ARM64: `STATUS_ACCESS_VIOLATION` (T-131, open).
