# podcrates v0.60.0

The sixtieth release of podcrates. It carries the network labs of
`pod-lab` (from podnet's data, PodUtils/podnet#592), the probe rows of the
host classes of podssh and podnet, clap's `requires` in `pod-manual`, and
the checks of `pod-enter` through the upper layer of an overlay root.

## Crates

| Crate | Change | Consumers |
| --- | --- | --- |
| `pod-lab` | The network labs: `proxy-only`, `proxy-tls-reterminate`, `proxy-per-name`, `sni-allowlist`, `no-proxy-no-dns`, `ws-upgrade-refused` and `ipv6-only`, held with no root in a network namespace with no route out, with a stand-in CONNECT proxy and TLS server on its loopback and two CAs for each run; the command gets the proxy variables and `SSL_CERT_FILE`; no lab reaches the network (T-716; calls C725 to C729). The parts that the new rows of `pod-hostprobe` see read those rows, so `podlab check --report` gives holds or fails for them; `Expect::Value`, `Expect::Shows`, `Observe::LabCheck`; new parts `proxy-variable`, `no-proxy`, `cert-file` (T-714, T-715, T-745; calls C732 to C735) | each project |
| `pod-hostprobe` | 20 census rows of the host classes (88 in all): the sockets (bind alone, listen after bind, UDP, raw and packet sockets, a connect to the loopback), the files (`/dev/pts`, `/proc/self/exe`, the controlling terminal, the lines of the caller in `/etc/passwd` and `/etc/group`, a `noexec` home, `/etc/ssl` read-only), and the way out with no packet off the host (the proxy variables, `SSL_CERT_FILE`, the resolver, the default routes of IPv4 and IPv6). `Kind::Here`, `Outcome::value`, `verdict::items`; the schema names the rows (T-714, T-715, T-745) | podrunner, podvm, each project |
| `pod-manual` | `clap::read` gives clap's `requires` and `requires_if` as `Rule::Needs` (with its new field `value`), from a probe of the parser, as clap has no getter of them (T-726; call C737) | each command line |
| `pod-enter` | On an overlay root with the caller's upper directory, the checks before the fork (the working directory, the paths of the rules of the confinement, also of a joined exec) read the upper layer with its whiteouts and opaque directories, then the lower layer, with the volumes over both (T-750; call C738) | podvm |

## How a consumer takes it

Each podcrates dependency names the tag `v0.60.0`; `issue-sync.yml@v0.60.0` takes `podcrates_ref: v0.60.0`.

- Each project: the network classes of your lane in `LANES.md` now run (`podlab run proxy-only -- ...`).
- podnet: your `requires` rules come into your manual with no glue.
- podrunner: `podlab check PROFILE --report FILE` with a report of a user's host now gives holds or fails for the socket, file and network parts.

## Breaking

- `pod_hostprobe::probes::Kind` has the variant `Here`: an exhaustive match adds it, or calls `Probe::measure`. An older `pod-lab` refuses a report with the new rows (`UnknownRow`).
- `pod_lab`: 12 `LabFact` variants and `NetFact::LoopbackReaches` leave; `Expect::Value`, `Expect::Shows` and `Observe::LabCheck` are new.
- `pod_manual::Rule::Needs` has the field `value`.

## Known defect

- `pod-lab`: the rows that need a packet through the proxy or to a server (T-751), the SNI filter on each address and a default route of IPv6 (T-747), and a way out for live lanes (T-746) are open; `ipv6-only` refuses on a kernel with no IPv6.
- `pod-manual`: a `requires` of a group gives no rule (T-756, open).
- `pod-enter`: the opaque attribute of an overlay in a user namespace is not measured (T-755, open).
- The installer core: no signature check of the assets (T-717, open); not tested on macOS and Windows (T-718, open).
- `pod-egress`: a failed TLS handshake or upgrade on VLESS, VMess and Trojan is `WebSocket`/`Unavailable` (T-652, open).
- `pod-gsr` on Windows ARM64: `STATUS_ACCESS_VIOLATION` (T-131, open).

## Publish
