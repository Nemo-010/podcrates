# podcrates v0.61.0

The sixty-first release of podcrates. It carries a way out of the network
labs of `pod-lab` for the live lanes of the consumers, the rows of
`pod-hostprobe` that send a packet out (off by default) with the check of
the network classes against them, and the signature of `SHA256SUMS` in the
installer core.

## Crates

| Crate | Change | Consumers |
| --- | --- | --- |
| `pod-lab` | `podlab run --way-out` (`Options::way_out`): for a profile with a stand-in proxy, the stand-in applies the rules of its class, then sends a `CONNECT` to a name that is not of the lab to the real network, directly or through the proxy of the host with its credential. The command never gets the proxy of the host; a direct way out does not dial the loopback of the host; `podlab run --way-out` is not dumpable (T-746). The parts of the network classes that need a packet out read the new rows of `pod-hostprobe` (`proxy-reaches`, `proxy-credential`, `port-refused`, `tls-reterminated`, `ssh-port-silent`, `answer-per-name`, `sni-reset`, `literal-reaches`, `ipv6-reaches`); a lab measures them against its stand-ins (`net::lab_targets`); `podlab check PROFILE --network NAME:PORT` (`--network-other`, `--network-literal`, `--network-closed`) runs them on a host (T-751) | each project |
| `pod-hostprobe` | `Settings::network` (`Network`), off by default; nine census rows of `Kind::Network` (`probes::NETWORK_ROWS`): `CONNECT` through the proxy of the host (with and with no credential, another name, a closed port, a literal), a ClientHello of TLS 1.2 (the certificate of `SSL_CERT_FILE` that issued the chain), a lookup. With no setting each row is a skip that names it; the schema names the rows (T-751) | podrunner, podvm, each project |
| `pod-hostprobe` (fix) | `probes::chroot_usable` reads the row of the caller's own chroot alone (`probes::CHROOT`): the leg through a user namespace of `v0.59.0` made it true on a host that refuses `chroot` to the caller (T-758, PodUtils/podvm#443) | podvm |
| `pod-term` | Tests only: the tmux oracle of the calibration keeps one idle session (T-757) | |

## The installer core

- `scripts/install/core-net.sh`: where `cosign` is on the host and the run
  is not offline, the core checks the keyless signature of `SHA256SUMS`
  (the identity of `release.yml` at the tag) and each pin against it; a
  failed check is a refusal (T-717, call C741). `release.yml` signs
  `SHA256SUMS` and attaches the bundle. This release is the first run of
  the signature.
- `nightly.yml`, job `install-os`: the test of the installer on
  `macos-15` and `windows-2025` (Git Bash) (T-718, call C740).

## How a consumer takes it

Each podcrates dependency names the tag `v0.61.0`; `issue-sync.yml@v0.61.0` takes `podcrates_ref: v0.61.0`.

- Each project: a live lane runs in a network class with
  `podlab run --way-out PROFILE -- CMD`.
- podvm: drop the shadow of `chroot_usable` (PodUtils/podvm@T-1921).
- podrunner, each project: `podlab check PROFILE --network NAME:PORT` on a
  user's host gives holds or fails for the parts of a CONNECT and of a
  handshake; a report of `pod-hostprobe` holds these rows where its caller
  set `Settings::network`.
- Each installer on the core: give `cosign` to the host to check the
  signature of `SHA256SUMS`.

## Breaking

- `pod_hostprobe::Settings` has the field `network`; `probes::Kind` has the
  variant `Network`: a struct literal names the field, and an exhaustive
  match adds the variant or calls `Probe::measure`. An older `pod-lab`
  refuses a report with the new rows (`UnknownRow`).
- `pod_lab::Options` has the field `way_out`. The network facts of a part
  that a row now reads are `Observe::LabCheck`, not `Observe::Lab`.

## Known defect

- `pod-lab`: the SNI filter on each address and a default route of IPv6
  (T-747) are open; `upgrade-refused` has no row; `ipv6-only` refuses on
  a kernel with no IPv6.
- `pod-manual`: a `requires` of a group gives no rule (T-756, open).
- `pod-enter`: the opaque attribute of an overlay in a user namespace is
  not measured (T-755, open).
- The installer core: T-717 and T-718 stay partial until the first run of
  the signature at this tag and of the job `install-os`.
- `pod-egress`: a failed TLS handshake or upgrade on VLESS, VMess and
  Trojan is `WebSocket`/`Unavailable` (T-652, open).
- `pod-gsr` on Windows ARM64: `STATUS_ACCESS_VIOLATION` (T-131, open).

## Publish

`publish.yml` runs on the tag: the dry run of `cargo publish --workspace`.
The switch `crates-io` of `Cargo.toml` is false (the owner, 2026-11-09).
