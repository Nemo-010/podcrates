# podcrates v0.65.0

The sixty-fifth release of podcrates. It carries the asks of the
consumers after v0.64.0: a PID namespace of the namespace rung of
`pod-enter` (podvm, podrunner), a node of `pod-relay` that stops on a lost
socket that its relay holds (podnet), a link of the resumable layer on the
HTTP road (podssh), the built-in roots in the certificate file of a way
out of `pod-lab` (podvm), four forms of the model of `pod-manual` (podssh),
and a `socks5://` proxy of `pod-iroh` that gets the address of the relay.

## Crates

| Crate | Change | Consumers |
| --- | --- | --- |
| `pod-enter` | `Plan::pid_namespace`: the namespace rung clones its child with `CLONE_NEWPID` (and `CLONE_NEWUSER` where the rung makes a user namespace, so that it owns the PID namespace), mounts a fresh `proc` of it, and keeps the child as pid 1, an init: the payload is pid 2; the init gives it SIGHUP, SIGINT, SIGQUIT, SIGUSR1, SIGUSR2, SIGTERM and SIGWINCH from a process (not from the terminal), reaps each orphan, and exits with the code of the payload. The `Child` is the host pid of the init. A join of such a run enters the PID namespace for the payload of the exec. Each other entry refuses the plan; the rung does not fall back to chroot with it (T-806, PodUtils/podvm#457; call C769) | podvm, podrunner |
| `pod-relay` | `Settings::lost_hold` (`LOST_HOLD`, 60 s): after a loss, a node that the relay answers `409` for its own socket for longer ends with `Exit::NameInUse` and the line of `held_line`; `rejoin` stays the bound of the whole wait (T-805, PodUtils/podnet#604; call C770). A link of the resumable layer on the HTTP road: `http_road::client::open_layer` (`OPEN_LAYER`, `ONE_LAYER`, `layer_route`), `forward_layer::Dialer::link_or_road` and `carry_or_road`, which take the road once the way refused the upgrade of a link; `forward_layer::Link`; `way_refusal::upgrade_refused`, moved from `pod-piping` (T-801, PodUtils/podssh#287; call C771) | podnet, podssh |
| `pod-lab` | The certificate file of a way out holds the built-in roots of `webpki-root-certs` on a host with no bundle; an `SSL_CERT_FILE` of the host that does not read, or that holds no certificate, refuses the way out with its name (T-797, PodUtils/podvm#455) | each project |
| `pod-manual` | An empty reason of an ignored or a refused flag writes the short sentence alone; `FlagKind::NotInRelease { code, why }`; `Command::availability` (`Availability::Feature { name, why, code }`): the help, the page and the JSON say that only a build with the feature has the command; `Command::topics`: topics inside the section of a command. `check::model` holds each new exit code to EXIT STATUS (T-807, PodUtils/podssh#288) | each project |
| `pod-iroh` | A `socks5://` proxy gets the address of the relay, which the resolver of the dial gives; `socks5h://` keeps the name (the patch 0002 of the fork of iroh-relay; T-808). The trial of podssh passes (T-810) | podssh |
| `pod-piping` | `probe::upgrade_refused` is `pod_relay::way_refusal::upgrade_refused`, by the same path | podssh |

## Tests and checks

The user namespace leg runs the PID namespace as root and as uid 65534:
pid 2, a fresh proc with no pid of the host, a SIGTERM to the init that
ends the payload, the end of each process of the namespace with the init,
and a join that lands in the namespace (`tests/userns/pid.rs`). A stand-in
role in memory serves the layer on the HTTP road; a session resumes over
the split, serial and one-POST forms after a cut (`tests/http_road_layer.rs`).
Each change has its plants.

## How a consumer takes it

Each podcrates dependency names the tag `v0.65.0`; `issue-sync.yml@v0.65.0` takes `podcrates_ref: v0.65.0`.

- podvm, podrunner: set `Plan::pid_namespace` for the namespace rung, and say it in your banner. A struct literal of `Plan` names the field. `podvm stop` sends its signal to the init, which gives it to the payload.
- podnet: a node ends with `Exit::NameInUse` after 60 s of `409` for its lost socket, with one line: take a new pair, or another relay of the pool.
- podssh: keep your wait of `rejoin` with `lost_hold: Settings::default().rejoin`, or take the hold. Serve `OPEN_LAYER` and `ONE_LAYER` in your role (give the session's bytes to your layer as one link), and call `link_or_road` and `carry_or_road` in `relay_layer.rs`.
- podssh: your text, help and JSON can move to `pod-manual` with the four forms.
- podssh: take `pod-iroh` with this tag (`adoption/podssh/pod-iroh.patch`).
- Each project with a lab with a way out: a scratch image with no bundle gets the built-in roots.

## Breaking

- `pod_enter::Plan` has the field `pid_namespace`: a struct literal names it.
- `pod_manual::Command` has the fields `availability` and `topics`, and `FlagKind` the variant `NotInRelease`: a struct literal with no `..Command::default()`, and a `match` with no wildcard, name them.
- `pod_relay::forward_layer::Missed` has the variant `Road`.
- A node of `pod-relay` ends after 60 s of `409` for its lost socket, not after `rejoin`.

## Known defect

- `pod-session`: the cause of the stalled resume of PodUtils/podssh#283 is open (T-767, partial); a spare waits 20 s when a full link holds the writer (T-768, open).
- `pod-enter`: the ids of the plan do nothing for a caller that is root of the initial namespace (T-791, open, when a consumer asks).
- The nightly: armv7 (T-789), riscv64 (T-766).
- `pod-iroh`: the relay dial takes a proxy URL, not the caller's dialer (T-809).
- `pod-link`: the tcp carrier allocates about 3 times for each `DATA` frame, in its TLS (T-798).
- `pod-lab`: `upgrade-refused` has no row; `ipv6-only` refuses on a kernel with no IPv6.
- `pod-gsr` on Windows ARM64: `STATUS_ACCESS_VIOLATION` (T-131, open).
