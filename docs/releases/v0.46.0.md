# podcrates v0.46.0

The forty-sixth release of podcrates. It carries the warm start of
`pod-guest` and a guard that stops the emulator on each error
(PodUtils/podvm#350, #370), the S3 carrier and the split session of
`pod-link` for podnet (PodUtils/podnet#521), and fixes of `pod-extract`,
`pod-hostprobe` and `pod-udf`.

## Crates

| Crate | Change | Consumers |
| --- | --- | --- |
| `pod-guest` | `warm`: `stage_idle`, `save`, `restore`, `start` (a warm start from a saved state, with a fingerprint and a cold boot when it does not hold) (T-596, PodUtils/podvm#350 item 7, calls C500 to C507); the provision, `run` and the warm restore stop the emulator on each error after the spawn (T-622, PodUtils/podvm#370, call C522) | podvm |
| `pod-link` | `s3::S3` and `S3Listener`: a simplex carrier over a bucket of the S3 API, behind the feature `s3` (T-494, calls C489 to C491); `split::Split` and `SplitListener`: one session over an up carrier and a down carrier, with `split::Lost` (T-500, calls C492, C493); a poll listener keeps no whole body and caps its connections (`Poll::max_connections`, `Stats::turned_away`) (T-525, call C488) | podnet |
| `pod-extract` | `open_tree` and the removal walk with one directory open, and refuse a tree past `MAX_DEPTH` (4096) (`TooDeep`); a name that is not UTF-8 is removed (T-615, call C510) | podvm, podnet |
| `pod-hostprobe` | the signal calls, the open flags and the errno numbers come from `linux_raw_sys` for the target (mips, sparc) (T-618, T-619, calls C511, C521); `CBuf::from_bytes`; `sys::signalfd` | podvm |
| `pod-udf` | tests against images of genisoimage and mkudffs (T-601, call C512) | podvm |
| `pod-warp` | the tests hold their dead port (T-621, call C520) | none |

CI runs as root the tests that start a worker of uid 1000 (T-614, call
C513).

## How a consumer takes it

Each podcrates dependency names the tag `v0.46.0`.

- podvm: `warm::start` for a warm start (QEMU 11 for the NVMe disks of the
  Windows plan; QEMU 8.2 refuses their state, and `start` boots cold).
- podnet: the S3 carrier (feature `s3`) and `split::Split`; podnet's
  question on E7-1 is answered on the hand-off.

## Breaking

- `pod-link`: `Poll` has the field `max_connections`. A struct literal
  names it.
- `pod-extract`: a tree deeper than 4096 levels is `TooDeep`.

## Known defect

- `pod-warp`: after a key that is not the pinned one, the client dials only
  the first door of the new record (T-624, open).
- `pod-link`: the S3 carrier is proven against a stand-in only (T-623,
  open).
- `pod-guest`: the next command of a guest in keep-alive mode is not
  proven on a real guest (T-602); no NTFS or hive writer (T-617, blocked).
- `pod-netlab`: five value sets of sand-net have no source (T-586,
  partial).
- `pod-gsr` on Windows ARM64: `STATUS_ACCESS_VIOLATION` (T-131, open).

## Publish

`publish.yml` runs on the tag: the dry run of `cargo publish --workspace`.
The switch `crates-io` of `Cargo.toml` is false (the owner, 2026-11-09).
The owner reserves `pod-actions-store`, `pod-actions-results`, `pod-udf`
and `pod-qga` on crates.io before a publish ("Owner actions" of
`TODO/PROGRESS.md`).
