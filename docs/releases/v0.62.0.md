# podcrates v0.62.0

The sixty-second release of podcrates. It carries the servers of the
command behind the rules of a network lab (podssh's lane), the proxy
variables of other tools in a lab, the ids inside the user namespace of
`pod-enter` (podvm and podrunner), the line of the far end at each resume
of `pod-session` (podssh's stalled resume), and the fixes of five tests of
the nightly.

## Crates

| Crate | Change | Consumers |
| --- | --- | --- |
| `pod-lab` | `podlab run --serve PORT` (more than one) and `--serve-ca FILE` (`Options::serve`, `Options::serve_ca`): after the rules of its class (the credential, the ports, 504, a reset, the silent port), the stand-in proxy sends a `CONNECT` to a name of the lab at a served port to the server of the command on `127.0.0.1:PORT` of the lab; where the class re-terminates the name, the proxy shows a leaf of its CA and checks the command's server with the roots of `--serve-ca` (502 with no roots); `ws-upgrade-refused` refuses the upgrade; in `sni-allowlist` a ClientHello of a listed name goes to the first served port. `podlab` refuses port 0, 443 or 3128, and `--serve` on a profile with no network lab (T-759, PodUtils/podssh#282; calls C747 to C749). A network lab removes the proxy variables of other tools (global-agent of Node.js, npm, Yarn, a build of Docker, the Google Cloud CLI) or sets them to its stand-in proxy, and removes the options of a proxy from the options of a Java virtual machine (`net::vars`, T-760). A spliced stream of the way out with no traffic for 30 s is no longer cut | each project |
| `pod-enter` | `Plan::userns_ids`: the uid and the gid of the payload inside the user namespace of the namespace rung (`None`: 0, as before). The payload of an image with `USER` runs as that user, with no capability; an exec that joins a run keeps the ids of the run (T-786, PodUtils/podvm#447; calls C757, C758) | podvm, podrunner |
| `pod-hostprobe` | `userns::map_line(inside, id)`, `Maps::with_inside`, `Maps::of_caller_inside` (T-786). The probe legs keep the map to 0 | podvm |
| `pod-session` | The far end writes the event `session.resume` (`RESUME`, Info, on the sink of `Keeper::with_tell`) at each resume: its number, the link that carries it (`Accepted::by`, `far::serve_admitted_by`), the offsets of both ends, the bytes it sends again, and what held the session (no link, the first link, an older resume that gave way) (T-767, partial: the cause of the stall is open; call C743) | podssh |
| `pod-relay` | The node names the relay session of each resume in that line | podssh |

## Tests

The nightly at `f309b07` is green on each target but ppc64le and armv7
(T-788, T-789) and riscv64 (T-766): T-761 (the lab test on a target where
a seccomp filter cannot hold), T-762 (a mount flag that qemu-user does not
fill), T-763 (a POST on TLS that the test did not flush), T-764 (the tick of
the timer of Windows), T-765 (a freed port on macOS).

## How a consumer takes it

Each podcrates dependency names the tag `v0.62.0`; `issue-sync.yml@v0.62.0` takes `podcrates_ref: v0.62.0`.

- podssh: run your relay role in each network lab with `podlab run --serve PORT [--serve-ca FILE]`; keep the node's lines of your m6 test: the next stall says which end holds the bytes (`session.resume`).
- podvm, podrunner: fill `Plan::userns_ids` from the image's `USER` or `--user` for `run -d` and `create` on the namespace rung.

## Breaking

- `pod_hostprobe::userns::map_line` takes the inside id first: `map_line(inside, id)`.
- `pod_enter::Plan` has the field `userns_ids`; `pod_lab::Options` has the fields `serve` and `serve_ca`: a struct literal names them.
- `pod_session::far::Accepted` has the builder `by`; the far end writes one more event at each resume.

## Known defect

- `pod-session`: the cause of the stalled resume of PodUtils/podssh#283 is open (T-767, partial); a spare waits 20 s when a full link holds the writer (T-768, open).
- The installer core: a tree copy with no pins stops on a host with cosign (T-773, open).
- `pod-enter`: the ids of the plan do nothing for a caller that is root (T-787, open).
- The nightly: ppc64le (T-788), armv7 (T-789), riscv64 (T-766).
- `pod-lab`: the SNI filter on each address and a default route of IPv6 (T-747); `upgrade-refused` has no row; `ipv6-only` refuses on a kernel with no IPv6.
- `pod-manual`: a `requires` of a group gives no rule (T-756, open).
- `pod-gsr` on Windows ARM64: `STATUS_ACCESS_VIOLATION` (T-131, open).
