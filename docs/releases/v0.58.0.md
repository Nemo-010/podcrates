# podcrates v0.58.0

The fifty-eighth release of podcrates. It carries the gaps of
`pod-manual` that podnet found (PodUtils/podnet#589), the way out to a
proxy in a lab (PodUtils/podssh#278), and part 1 of the one installer core
of the projects (the owner's ruling "Installer").

## Crates

| Crate | Change | Consumers |
| --- | --- | --- |
| `pod-manual` | `clap::read` takes clap's `env` of each flag and argument; a rule that names a positional argument passes `check::model`; command groups and a "Start here" block in the model and the help (`Command::groups`, `Command::lead`); the variable scanner reads only the calls that read the environment (`scan::CALLS`, `scan::LISTS`); the feature `clap` turns on `clap/env` (T-725; calls C713 to C716) | each command line |
| `pod-lab` | `Options::allow_connect` and `podlab run --allow-connect PORT`: a TCP connect may reach PORT where a profile refuses each TCP connect (`bind-denied`) (T-737). `podlab --help` comes from the model, with groups and a lead | podssh, each project |
| `pod-transit` | Tests only: the harness of the transit relay takes only its own child's listener (T-731; call C717) | |

## Scripts and workflows

- `scripts/install/`: the installer core in POSIX `sh` (`core.sh`), the installer of `podlab`, the writer of the pins (`pins.py`) and the test (`test.sh`) (T-702 part 1; calls C706 to C712). `docs/install.md` tells a project how to build its installer on it.
- `release.yml` builds static `podlab` for `x86_64` and `aarch64` musl and attaches it, `podlab-install.sh` (with its pins), the offline bundle and `SHA256SUMS`.
- `ci.yml`: the job `install` runs the test of the installer with `--strict`.
- `scripts/check-strings.py` and `scripts/check-man.sh`: no false positive on podnet's release binary (T-725). `scripts/check-size.py` reads `.sh` and `.py` too.

## How a consumer takes it

Each podcrates dependency names the tag `v0.58.0`.

- podnet: drop `fill_env`, the filter of the rules, and 7 words of `EXEMPT`; `--help` can come from the model (`Command::groups`, `Command::lead`).
- podssh: `podlab run --allow-connect PORT bind-denied -- ...` with the port of your proxy (`crates/pod-lab/LANES.md`).
- Each project: build your installer on `scripts/install/core.sh` at this tag (`docs/install.md`).

## Breaking

- `pod_manual`: new fields `Command::groups`, `Command::lead` and `Arg::env`: a struct literal names them or takes `..Default::default()`. `scan::variables_read` no longer reports a quoted word outside a call. `check::variables` reads the variables of the model.
- `pod_lab::Options`: a new field `allow_connect`.

## Known defect

- `pod-manual`: the reader of clap gives no `Rule::Needs` (T-726, open).
- The installer core: no signature check of the assets (T-717, open); not tested on macOS and Windows (T-718, open).
- The plant `enter-userns-dev-no-remount` misses where the host's `/dev` has `nosuid` and `noexec` (T-736, open); five harnesses keep a port race (T-732, open).
- `pod-egress`: a failed TLS handshake or upgrade on VLESS, VMess and Trojan is `WebSocket`/`Unavailable` (T-652, open).
- `pod-gsr` on Windows ARM64: `STATUS_ACCESS_VIOLATION` (T-131, open).
