# podcrates v0.63.0

The sixty-third release of podcrates. It carries the ids of the plan for a
caller that is uid 0 of a nested user namespace (podvm's foreground run),
the installer core for a copy of a project's tree, the rule "needs one of"
of `pod-manual`, and a fix of a test of the nightly.

## Crates

| Crate | Change | Consumers |
| --- | --- | --- |
| `pod-enter` | Where `Plan::userns_ids` names ids and the caller is uid 0 of a user namespace that is not the initial one, the child opens a nested user namespace after the mounts and before the `chroot` (`<uid> 0 1`, `<gid> 0 1`), so the payload runs as those ids with no capability. Each entry with a chroot takes the step: the namespace rung, the chroot rung and the ladder. A failed step is a refusal with its step (37 to 40) and no fall back. A host root (the initial namespace) is unchanged (T-787, PodUtils/podvm#452; calls C759, C760) | podvm |
| `pod-hostprobe` | `userns::is_initial_map` (T-787) | podvm |
| `pod-manual` | `Rule::Needs` has the field `one`: a need of one of the names. `clap::read` gives a `requires` of a group as "--audit needs one of --json, --text." in the help, the text, the man page, the JSON (`"one": true`; an older JSON reads as a need of each name) and `llms-full.txt`; `check::model` refuses a need of one of fewer than two names (T-756; call C762) | each command line |
| `pod-testkit` | `nobody::again_as_root_of_a_user_namespace` (T-787) | the tests |

## The installer core

A copy whose block of pins is empty (a copy of a project's tree that sets
its pins at run time, as podnet's does from the signed `SHA256SUMS`) is not
compared with `NAME-install.sh` of `SHA256SUMS`; one line says so. A stamped
installer keeps the compare (T-773, PodUtils/podnet#597). The default hook
`inst_version_ok` carries the `disable` of SC2317 of each hook
(PodUtils/podssh#284).

## Tests

`pod-enter`'s `pass_clear` test checks the identity of a directory of its own,
not a closed number that another thread can take (T-788, the nightly on
ppc64le).

## How a consumer takes it

Each podcrates dependency names the tag `v0.63.0`; `issue-sync.yml@v0.63.0` takes `podcrates_ref: v0.63.0`.

- podvm: a foreground `run` fills `Plan::userns_ids` as `run -d` does; the payload runs as the user of the image.
- Each project with an installer: take `core.sh` and `core-net.sh` of this tag; a copy of the tree that sets its pins at run time needs no replacement of `inst_signature`.
- Each command line: a `requires` of a group comes into the manual with no glue.

## Breaking

- `pod_manual::Rule::Needs` has the field `one`: a struct literal or a pattern names it or uses `..`.

## Known defect

- `pod-session`: the cause of the stalled resume of PodUtils/podssh#283 is open (T-767, partial); a spare waits 20 s when a full link holds the writer (T-768, open).
- `pod-enter`: the ids of the plan do nothing for a caller that is root of the initial namespace (T-791, open, when a consumer asks).
- The nightly: armv7 (T-789), riscv64 (T-766).
- `pod-lab`: the SNI filter on each address and a default route of IPv6 (T-747); `upgrade-refused` has no row; `ipv6-only` refuses on a kernel with no IPv6.
- `pod-gsr` on Windows ARM64: `STATUS_ACCESS_VIOLATION` (T-131, open).

## Publish

`publish.yml` runs on the tag: the dry run of `cargo publish --workspace`.
