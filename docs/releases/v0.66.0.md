# podcrates v0.66.0

The sixty-sixth release of podcrates. It carries the fix of the PID
namespace of `pod-enter` that podvm found when it took `v0.65.0`, and the
writes of the management API of `pod-devtunnel`.

## Crates

| Crate | Change | Consumers |
| --- | --- | --- |
| `pod-enter` | The init of a PID namespace and the relay of a join close each descriptor of the caller before their loop: a fork with no exec kept each one, the ready pipe of `pod-supervise` too, so `podvm run -d` never returned (T-811, PodUtils/podvm#460) | podvm, podrunner |
| `pod-hostprobe` | `sys::close_from(first)`: `close_range`, else a close of each number | each project |
| `pod-devtunnel` | The writes of the management API: `Management::list` (each tunnel of the user, of each cluster), `create` (an id of the vendor's form from `new_id`, a name, a cluster or the global host), `delete`, `add_port`; `Owned`, `OwnedPort`. The stand-in serves them (T-378, part 2, step 1; GitHub #94) | podssh |
| `pod-services` | The facts of the writes in `microsoft-devtunnel.toml`, each with its source in the vendor's client | each project |

## Tests and checks

A live test of the user namespace leg: a caller that waits for the end of
file of a pipe with close-on-exec returns while the payload of a PID
namespace and the exec of a join run, as root and as uid 65534; the plant
`enter-pid-init-keeps-fds`. `tests/writes.rs` of `pod-devtunnel` against
the stand-in, with two plants.

## How a consumer takes it

Each podcrates dependency names the tag `v0.66.0`; `issue-sync.yml@v0.66.0` takes `podcrates_ref: v0.66.0`.

- podvm, podrunner: set `Plan::pid_namespace` for `run -d`: the launcher of `pod-supervise` gets the end of file of its ready pipe at the exec of the payload.
- podssh: `pod-devtunnel` can list, make and delete tunnels, and add a port, with a user token.

## Breaking

- None.

## Known defect

- `pod-session`: the cause of the stalled resume of PodUtils/podssh#283 is open (T-767, partial); a spare waits 20 s when a full link holds the writer (T-768, open).
- `pod-enter`: the ids of the plan do nothing for a caller that is root of the initial namespace (T-791, open, when a consumer asks).
- `pod-devtunnel`: no device-code flow and no token store yet (T-378, partial).
- The nightly: armv7 (T-789), riscv64 (T-766).
- `pod-iroh`: the relay dial takes a proxy URL, not the caller's dialer (T-809).
- `pod-link`: the tcp carrier allocates about 3 times for each `DATA` frame, in its TLS (T-798).
- `pod-gsr` on Windows ARM64: `STATUS_ACCESS_VIOLATION` (T-131, open).

## Publish
