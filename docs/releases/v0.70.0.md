# podcrates v0.70.0

The seventieth release of podcrates. It carries the defects and asks that
the consumers found today: the staged tree of a root run of podvm, the
evidence of a Windows run that times out, the CA file of the consumer on
the WebSocket roads, a broker on a host whose names resolve only through
its proxy (a blocker of podrunner's release), the place of an unknown need,
the headers of Access on the probe of a node, and a check of the examples
of a manual. It also carries the wire document of the relay with its
test vectors.

## Crates

| Crate | Change | Consumers |
| --- | --- | --- |
| `pod-enter` | `stage::copy_tree` makes each character or block device of the tree again with `mknod(2)`, with its mode and number, where `mknod(2)` passes; else it skips and counts it. It returns `Staged { entries, nodes_skipped }`. A fifo or a socket stays a refusal. A run of root with `PODVM_MODE=rundir` or `tmpfs` stages again (T-857, PodUtils/podvm#467) | podvm, podrunner |
| `pod-tls` | `Context::roots_for(&Trust::Default)`, and so `config_for`, take `Settings::ca_file` (the CA file alone), as `roots()` and `client_config_with` do: each road of `pod-ws` and `pod-relay` trusts the CA of the consumer behind a proxy that signs TLS; an unusable CA file is an error, not a fall back (T-858, PodUtils/podnet#608) | each project |
| `pod-broker` | With `Settings::names_upstream`, a name that the policy allows and that has no local answer (no resolver on the host, no address, a timeout) goes to the upstream, which resolves it; the audit line says `"resolved":"upstream"`. The deny of a name, the policy and the canary hold. Address mode keeps the refusal (call C777; T-862, PodUtils/podrunner#215) | podrunner, podvm |
| `pod-guest` | The mailbox agent writes a line to `COM1`, the serial log of the run, when it starts, when it finds the mailbox and when it gives up; with `Settings::evidence`, a run that timed out keeps that log and a screen (T-861, PodUtils/podvm#468) | podvm |
| `pod-actions-workflow` | The error of an unknown need gives the place of the id that names no job, not of the job (`Job::needs_marks`; T-859, PodUtils/podrunner#214) | podrunner |
| `pod-piping` | The probe of a node's upgrade carries the headers of the caller (`Way::extra`), masked in a refusal (T-860, PodUtils/podssh#306) | podssh |
| `pod-manual` | `check::examples(manual, parse)`: each example of the program against its parser, beside `check::flags` (T-867, PodUtils/podnet#649) | each project |
| `pod-relay` | `docs/wire.md`, the wire of the relay (version 1), and its 117 vectors (`crates/pod-relay/tests/vectors/`), from podssh at `04f141b`: 109 run through `pod-session`, `pod-relay` and `pod-ws` (`tests/wire_vectors.rs`); the 8 of `tokens.json` wait for the relay role (T-856). `scripts/check-wire-vectors.py` reads them from the page alone, in CI (T-120, PodUtils/podssh#304) | podssh, podnet |

## Tests and checks

- `pod-enter`: `a_device_entry_goes_to_the_maker_with_its_mode_and_number` (on `/dev/null`, with no root), `a_device_node_is_made_again_where_mknod_passes` and `a_device_node_is_skipped_and_counted_where_mknod_fails` (each of the two skips with a line where the fixture's `mknod(2)` fails).
- `pod-tls`: `the_default_trust_takes_the_ca_file_of_the_settings`.
- `pod-relay`: `tests/wire_vectors.rs`; `scripts/check-wire-vectors.py` and its plant.
- New plants: `enter-stage-refuses-a-device-node`, `tls-default-trust-ignores-the-ca-file`, `wire-pong-fields-swapped`, `actions-unknown-need-marks-the-job`, `piping-probe-without-headers`, `guest-agent-silent-before-the-mailbox`, `broker-names-mode-needs-a-local-resolver`, `manual-examples-not-parsed`.
- `pod-cloudflare`: podnet took the crate at `00b54ff`; its trial is removed and `SOURCES` takes the block (T-029 done).

## How a consumer takes it

Each podcrates dependency names the tag `v0.70.0`; `issue-sync.yml@v0.70.0` takes `podcrates_ref: v0.70.0`.

- podvm: `copy_tree` returns `Staged`; read `entries` where it read the count.
- podnet: `Trust::Default` takes the CA file now; `podnet_core::trust::ws_trust()` (its T-421) can go.
- podssh: `docs/wire.md` and the vectors are the same as yours at `04f141b`; a change of a vector needs a new version of the page. Drop the skip of the piping probe for a host with Access (`process_names`).
- podrunner: names mode sends a name that only the upstream resolves; an unknown need names its own line.
- podvm: the agent's lines on the serial log come with the next provision of an image (the installer copies the agent); set `Settings::evidence` to keep the screen and the serial log of a timeout.
- Each: `pod_manual::check::examples` and `check::flags` test each promise of the help against the parser.

## Breaking

- `pod_enter::stage::copy_tree` returns `Staged`, not `usize`.
- `pod_tls::Context::roots_for(&Trust::Default)` gives the CA file alone where the settings name one, and an error where it cannot be used.
- `pod_actions_workflow::Job` has a new public field (`needs_marks`).

## Known defect
