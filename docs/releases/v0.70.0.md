# podcrates v0.70.0

The seventieth release of podcrates. It carries two defects that consumers
found: the staged tree of a root run of podvm, and the CA file of the
consumer on the WebSocket roads of podnet. It also carries the wire
document of the relay with its test vectors.

## Crates

| Crate | Change | Consumers |
| --- | --- | --- |
| `pod-enter` | `stage::copy_tree` makes each character or block device of the tree again with `mknod(2)`, with its mode and number, where `mknod(2)` passes; else it skips and counts it. It returns `Staged { entries, nodes_skipped }`. A fifo or a socket stays a refusal. A run of root with `PODVM_MODE=rundir` or `tmpfs` stages again (T-857, PodUtils/podvm#467) | podvm, podrunner |
| `pod-tls` | `Context::roots_for(&Trust::Default)`, and so `config_for`, take `Settings::ca_file` (the CA file alone), as `roots()` and `client_config_with` do: each road of `pod-ws` and `pod-relay` trusts the CA of the consumer behind a proxy that signs TLS; an unusable CA file is an error, not a fall back (T-858, PodUtils/podnet#608) | each project |
| `pod-relay` | `docs/wire.md`, the wire of the relay (version 1), and its 117 vectors (`crates/pod-relay/tests/vectors/`), from podssh at `04f141b`: 109 run through `pod-session`, `pod-relay` and `pod-ws` (`tests/wire_vectors.rs`); the 8 of `tokens.json` wait for the relay role (T-856). `scripts/check-wire-vectors.py` reads them from the page alone, in CI (T-120, PodUtils/podssh#304) | podssh, podnet |

## Tests and checks

- `pod-enter`: `a_device_node_is_made_again_where_mknod_passes`, `a_device_node_is_skipped_and_counted_where_mknod_fails` (each skips with a line where the fixture's `mknod(2)` fails).
- `pod-tls`: `the_default_trust_takes_the_ca_file_of_the_settings`.
- `pod-relay`: `tests/wire_vectors.rs`; `scripts/check-wire-vectors.py` and its plant.
- New plants: `enter-stage-refuses-a-device-node`, `tls-default-trust-ignores-the-ca-file`, `wire-pong-fields-swapped`.

## How a consumer takes it

Each podcrates dependency names the tag `v0.70.0`; `issue-sync.yml@v0.70.0` takes `podcrates_ref: v0.70.0`.

- podvm: `copy_tree` returns `Staged`; read `entries` where it read the count.
- podnet: `Trust::Default` takes the CA file now; `podnet_core::trust::ws_trust()` (its T-421) can go.
- podssh: `docs/wire.md` and the vectors are the same as yours at `04f141b`; a change of a vector needs a new version of the page.

## Breaking

- `pod_enter::stage::copy_tree` returns `Staged`, not `usize`.
- `pod_tls::Context::roots_for(&Trust::Default)` gives the CA file alone where the settings name one, and an error where it cannot be used.

## Known defect

- `pod-session`: the cause of the stalled resume of PodUtils/podssh#283 is open (T-767, partial); a spare waits 20 s when a full link holds the writer (T-768, open).
- `pod-cloudflare`: the pin of cloudflared is 2026.10.7, and 2026.11.0 has the same files (T-851); two `Protocol` types (T-853).
- The nightly: armv7 (T-789), riscv64 (T-766).
- `pod-iroh`: the relay dial takes a proxy URL, not the caller's dialer (T-809).
- `pod-gsr` on Windows ARM64: `STATUS_ACCESS_VIOLATION` (T-131, open).
