# podcrates v0.48.0

The forty-eighth release of podcrates. It carries the fix of the
readiness of a Windows provision for podvm (PodUtils/podvm#372): a sign
that holds after a fixed time, and a screen sign that ignores a blinking
cursor.

## Crates

| Crate | Change | Consumers |
| --- | --- | --- |
| `pod-guest` | `ready::Sign::After(time)`: holds once `time` passed since the start of `ready::wait`; `Sign::Screen { settle }` reads each dump as a P6 PPM, takes a change inside a box of 32x32 pixels (`ready::CURSOR`) as no change, and holds only on a screen that differs from the first dump and is not blank; the text of a failed wait names each sign (T-633, calls C591 to C594; C592 replaces the rule of C452) | podvm |

## How a consumer takes it

Each podcrates dependency names the tag `v0.48.0`.

- podvm: pass `Ready { signs: vec![Sign::After(t)], deadline: > t, every:
  ready::EVERY }` under KVM and TCG, with `t` the fixed wait of the
  provision before `v0.45.0` (240 s by default). Under KVM,
  `vec![Sign::Screen { settle: 15 s }, Sign::After(t)]` can end the wait
  sooner.
- podnet, podssh, podrunner: the bump of the tag only.

## Breaking

- `pod-guest`: `ready::Sign` has the variant `After`. A `match` names it.
- `pod-guest`: `Sign::Screen` holds on a screen that settles up to a
  change of 32x32 pixels and differs from the first dump; a blank screen
  does not hold.

## Known defect

- `pod-guest`: the warm restore gives the next command on the saved
  mailbox (T-628, open); the QMP commands name the drive by the
  deprecated `device` (T-632, open); the screen sign is not proven on a
  real Windows guest (podvm's next provision proves it).
- `pod-turn`: the check of a SHA-256 answer has no server of another party
  (T-631, open).
- `pod-netlab`: five value sets of sand-net have no source (T-586,
  partial).
- `pod-gsr` on Windows ARM64: `STATUS_ACCESS_VIOLATION` (T-131, open).
