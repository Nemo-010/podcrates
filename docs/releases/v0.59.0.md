# podcrates v0.59.0

The fifty-ninth release of podcrates. It carries the volumes of a plan in
`pod-enter` (PodUtils/podvm#440), the two defects that podnet's lane in
the labs found (PodUtils/podnet#592), a chroot row of `pod-hostprobe` in a
user namespace (PodUtils/podrunner#191), and two fixes of the tests.

## Crates

| Crate | Change | Consumers |
| --- | --- | --- |
| `pod-enter` | `Plan::volumes` (`VolumeBind { host, guest, read_only }`): the namespace rung, also through a user namespace, binds each volume after the device binds and before the `chroot`. The guest path is walked under the root with `openat2(RESOLVE_IN_ROOT \| RESOLVE_NO_SYMLINKS)`, and a missing directory or file is made. A read-only volume is remounted with the flags that the kernel locks. Each failure is a named step (33 to 36), with no fall back to chroot; a guest path through a link of the image is refused; a missing host path is refused before the fork; an entry with no mount namespace of its own refuses a plan with a volume (T-738; calls C720 to C722). A rule of the confinement on the guest path of a volume is checked through the volume, and holds on it (T-739; call C731) | podvm |
| `pod-link` | The unix carrier listens under Landlock with no `REFER`: on `EXDEV` it binds at the path; on Linux each listener has mode 0600 from its bind; a refused `listen` names `listen` (T-742; call C724) | podnet, podrunner |
| `pod-confine` | `Spec::compile_by`: the caller gives the opener of each path of a rule (T-739) | |
| `pod-hold` | The netns hold works where the host refuses UDP sockets (`udp-denied`): the interface ioctls use a TCP socket, with a datagram socket as the fallback (T-743; call C723) | podnet |
| `pod-hostprobe` | The census row `chroot(/tmp) in unshare(NEWUSER+maps)` (`probes::USERNS_CHROOT`), and its name in the schema of the report (T-744); `sys::fstatfs` and the constants of the atime flags (T-738) | podrunner, podvm |
| `pod-testkit` | `listener::{free_port, own_listener, start}`: a server of a test harness is up only when its own child holds each listener of its port (T-732; call C719); `nobody::again_over_a_bare_dev`, `nobody::again_over_a_flagged_tmpfs`, `nobody::mount_options` (T-736, T-738; call C718) | |
| `pod-wormhole`, `pod-relay`, `pod-services-watch`, `pod-dns`, `pod-oci`, `pod-transit` | Tests only: each harness takes `pod_testkit::listener::start` (T-732) | |

## How a consumer takes it

Each podcrates dependency names the tag `v0.59.0`.

- podvm: fill `Plan::volumes` from `-v HOST:GUEST[:ro]` for `run -d` and `create`, and drop the path rewrite of those volumes on the namespace rung; keep `unmount_under` before each removal of a tree. A volume and a rule of the confinement on its guest path combine.
- podnet: drop the waits on your T-380 and T-381.
- podrunner: show `mount(tmpfs,/tmp) in unshare(NEWUSER+maps,NEWNS)` and `chroot(/tmp) in unshare(NEWUSER+maps)` in `doctor` (PodUtils/podcrates#201).
- Each project: the issue sync at `issue-sync.yml@v0.59.0` with `podcrates_ref: v0.59.0`.

## Breaking

- `pod_enter::Plan` has the field `volumes`: a plan built with a struct literal names it (`volumes: Vec::new()`).

## Known defect

- `pod-enter`: on an overlay root with an upper directory, the working directory and the paths of the rules are checked in the lower layer before the fork (T-750, open).
- `pod-manual`: the reader of clap gives no `Rule::Needs` (T-726, open).
- The installer core: no signature check of the assets (T-717, open); not tested on macOS and Windows (T-718, open).
- `pod-egress`: a failed TLS handshake or upgrade on VLESS, VMess and Trojan is `WebSocket`/`Unavailable` (T-652, open).
- `pod-gsr` on Windows ARM64: `STATUS_ACCESS_VIOLATION` (T-131, open).
