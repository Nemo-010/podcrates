# podcrates v0.54.0

The fifty-fourth release of podcrates. It carries part 1 of `pod-lab`
(PodUtils/podrunner#180, PodUtils/podvm#424) and part 1 of `pod-manual`
(PodUtils/podnet#584), under the owner's ruling "Discipline".

## Crates

| Crate | Change | Consumers |
| --- | --- | --- |
| `pod-lab` | New. The hostile host classes as data: 16 profiles (the 10 of PodUtils/podrunner#180 and the 6 of PodUtils/podvm#424), each part with the rows of `pod-hostprobe` that it must make refuse or allow. `check` gives each part as holds, fails or unseen; `run` holds the parts that a host with no root can hold (a seccomp filter of `pod-confine`, Landlock, a tmpfs in a user namespace, descriptors 3 to 9), checks them from inside, and runs CMD only when each part holds (exit 125 else, unless `partial`). The static binary `podlab` (feature `cli`): `list`, `check`, `run`, `man` (T-692 part 1; calls C673 to C680) | podrunner, podvm, podnet, podssh |
| `pod-manual` | New. The help and the manual of a command line from one model that the program fills (a reader of `clap` behind the feature `clap`): the text, man(7), JSON and `llms.txt` writers, the pager (only on a terminal; `--no-pager`), and the checks that a program calls from its tests: the rules of the text (no emoji, no control character, no work id, short sentences), the drift of a generated file, the variables, the exit codes and the flags both ways, and `error::fault` (T-700 part 1; calls C682 to C687). Sources: podnet's `src/manual/` at `78a3911`, the generic part of podssh's `man/` at `cfc3ae3` | each command line |
| `pod-hostprobe` | `SYS_GETSOCKNAME`, `getsockname`, `Statfs::f_blocks`, the names of `EAFNOSUPPORT` and `EBADFD` (T-692) | |
| `pod-enter` | Tests only: the tests of `tests/userns.rs` run one at a time (T-713) | |

## Scripts

- `scripts/agent/watch.py` and `watch_test.py`: the one watcher of the organization (the owner's rulings "Watcher" and "Strangers"; T-710 to T-712; PodUtils/podcrates#186).
- `scripts/check-strings.py` (the text rules over the `.rodata` of a release binary) and `scripts/check-man.sh` (groff and mandoc with no warning).

## How a consumer takes it

Each podcrates dependency names the tag `v0.54.0`.

- Each project: the labs (PodUtils/podcrates#180): run your release in the profiles of your host classes with `podlab run PROFILE -- CMD`; a part that this host cannot hold stops the run with its reason.
- Each command line: the take of `pod-manual` (PodUtils/podcrates#181): fill the model from your own tables, give `CLI man [--no-pager]`, and call the checks from your tests. `podlab` (`crates/pod-lab/src/bin/podlab/`) is the example.
- podnet: `src/manual/` and `scripts/gen-llms.py` leave podnet when it takes `pod-manual`.

## Breaking

None for an existing crate.

## Known defect

- `podlab`: its usage errors come from clap, not in the form of `pod_manual::error::fault` (T-704, open).
- `check-strings.py` reads ELF only (T-705, open).
- `pod-lab`: `bind-denied` refuses TCP only (T-696, open); some parts are unseen in a check of a report (T-693 to T-695, open).
- `pod-egress`: a failed TLS handshake or upgrade on VLESS, VMess and Trojan is `WebSocket`/`Unavailable` (T-652, open).
- `pod-gsr` on Windows ARM64: `STATUS_ACCESS_VIOLATION` (T-131, open).
