# podcrates v0.49.0

The forty-ninth release of podcrates. It carries the fix of the pairing by
a code over the Nostr relays for podssh (PodUtils/podssh#247), the warm
restore of a Windows guest on a new mailbox medium and the mailbox device
named by id for podvm, and the proof of the SHA-256 answers of `pod-turn`
against xturn.

## Crates

| Crate | Change | Consumers |
| --- | --- | --- |
| `pod-wormhole` | `nostr::relay::Relay::close` reads the relay until each event of the end has its `OK`, then closes, so the last word of an end that closes at once reaches the other end; `nostr::relay::UNANSWERED_MOST` (64) (T-634, calls C595 to C597) | podssh |
| `pod-guest` | the USB mailbox is `usb-bot` with a removable `scsi-hd`, named by `id` (`plan::MAILBOX_ID`, `plan::MAILBOX_USB`); the QMP commands name the device by `id`, not by the deprecated `device` (T-632, call C583); the warm restore loads the saved mailbox unchanged and gives the command on a new medium after the load (`Swap::restored`); the save copies the medium that is in the guest (`swap::mailbox_file`); `save`, `restore` and `start` refuse an NVMe mailbox (T-628, calls C584 to C586) | podvm |
| `pod-turn` | the check of the MESSAGE-INTEGRITY-SHA256 of each answer, proved against xturn on the loopback (T-631, calls C587, C588) | podssh |

## How a consumer takes it

Each podcrates dependency names the tag `v0.49.0`.

- podssh: fill `Ends::relays` from `pod_services::of_kind("nostr-relay")`
  again (PodUtils/podssh#247).
- podvm: `warm::restore` takes the command of the agent and gives `(Child,
  Swap)`; `warm::start` gives `Started { child, how, swap }`; a warm start
  needs `Options::mailbox = MailboxBus::Usb`. The guest sees the USB
  mailbox as before (the same class and descriptors).
- podnet, podrunner: the bump of the tag only.

## Breaking

- `pod-guest`: `warm::restore(.., agent_cmd)` gives `(Child, Swap)`;
  `warm::start` gives `Started { child, how, swap }`; `save`, `restore` and
  `start` refuse an NVMe mailbox with `Usage`; the argv of a USB mailbox
  is `usb-bot` and `scsi-hd`.

## Known defect

- `pod-guest`: a warm start runs only from QEMU 11 with the NVMe root disk
  of the plan (T-635, open); the screen sign of T-633 is not proven on a
  real Windows guest.
- `pod-netlab`: five value sets of sand-net have no source (T-586,
  partial).
- `pod-gsr` on Windows ARM64: `STATUS_ACCESS_VIOLATION` (T-131, open).

## Publish
